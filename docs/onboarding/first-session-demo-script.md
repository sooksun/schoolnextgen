# สคริปต์ Demo Session ครั้งแรกกับครู Pilot

> เป้าหมาย: ครู Pilot 1 คน เปิดใช้งานจริง ทำ Reflection แรกได้ และเข้าใจว่า "ทำต่อทุกวัน 4 สัปดาห์" หมายถึงอะไร
>
> **เวลา:** 30-40 นาที (เผื่อคำถาม + setup ครั้งแรก)
> **ผู้นำเซสชัน:** ผู้พัฒนา/ผู้ดูแลระบบ (1 คน)
> **ผู้ร่วม:** ครู Pilot คนแรก (1 คน)
> **สถานที่:** หน้าจอเดียวกัน / Zoom + share screen / โต๊ะข้าง ๆ ก็ได้

## ก่อนเข้าเซสชัน (Checklist ของผู้นำ)

ทำให้เสร็จ **อย่างน้อย 1 ชั่วโมงล่วงหน้า**:

- [ ] Server `docker compose ps` แสดง app + mysql `up (healthy)`
- [ ] `/health` คืน `{"ok":true}` จาก URL ที่ครูจะใช้จริง (เช่น `https://snx.your.school/health`)
- [ ] **Smoke test AI สรุปจริง 1 รอบ** — login ด้วย `teacher@demo.local` (รหัสที่ rotate แล้ว) → สร้าง Reflection จริง 1 ตัว → กด "สรุปอัตโนมัติ" → ตรวจว่าได้ stream กลับมาภายใน ~15 วินาที. นี่คือการพิสูจน์ว่า `ANTHROPIC_API_KEY` ใช้งานได้จริง — ไม่ได้แค่ผ่าน Zod validation
- [ ] ลบ Reflection ทดสอบทิ้ง (หรือเหลือไว้ก็ได้ — แต่ห้ามใช้บัญชี demo กับครูจริง)
- [ ] **สร้างบัญชีใหม่ของครู Pilot** (อีเมลจริงของครู + รหัสชั่วคราว) ตาม [`admin-quickstart.md §6`](./admin-quickstart.md#6-add-real-pilot-teachers-10-min--for-each-new-teacher). **ห้ามใช้ `teacher@demo.local` กับครูจริง** — บัญชี demo เป็นของผู้ดูแลเท่านั้น
- [ ] เขียนข้อมูล login ลงกระดาษ/Note ส่วนตัว (URL + email + password) — **ไม่ส่งทาง LINE/Email** เพราะอาจเป็นบัญชีร่วม/ค้างบนเครื่องอื่น
- [ ] เปิด [`teacher-cheatsheet.md`](./teacher-cheatsheet.md) ทาง phone/tablet ของครูไว้แล้ว
- [ ] เตรียมแก้วน้ำให้ครูคนละแก้ว
- [ ] กระดาษ A4 + ปากกา (สำหรับครูจดสิ่งที่อยากแก้/เพิ่ม)

## 0-3 นาที: เปิดใจ

> "ขอบคุณคุณครูที่ตกลงเป็นคน**แรก**ของโรงเรียนที่จะใช้ระบบนี้นะคะ"

**ประเด็นที่ต้องสื่อ:**
1. **ครูช่วยทดลอง** — ระบบใหม่ ยังมีจุดที่ต้องปรับ. ทุกข้อที่ครูบอกว่า "ใช้แล้วงง" คือสิ่งที่จะแก้ทันที
2. **ไม่ใช่การประเมินครู** — Reflection ที่ครูเขียนใช้เพื่อพัฒนาตัวเอง + ขับเคลื่อน SAR ของโรงเรียน ไม่ใช่หลักฐานจับผิด
3. **AI เป็นผู้ช่วย ไม่ใช่ผู้ตัดสิน** — ครูยังคงเป็นเจ้าของบันทึก. AI แค่ช่วยร่าง
4. **ช่วงทดลอง 4 สัปดาห์** — ถ้าใช้แล้วไม่เวิร์ค เลิกได้ทันที. ครูไม่ติดสัญญาอะไร

ถามครู: **"คุณครูคาดหวังอะไรจากระบบนี้บ้างคะ?"** → จดคำตอบ (จะใช้ตอบเทียบหลัง 4 สัปดาห์)

## 3-8 นาที: Login + ทัวร์หน้าครู

**ทำพร้อมกัน** — ครูใช้เครื่องของตน, ผู้นำดูหน้าจอ

1. เปิด URL ระบบ
2. ใส่อีเมล + รหัสชั่วคราว → กด Login
3. หน้าครูเปิด — ชี้ให้ดูแบบเร็ว ๆ ไม่ต้องอธิบายลึก:
   - แถบบน: ชื่อโรงเรียน + ปีการศึกษา + เทอม (read-only)
   - Sidebar ซ้าย: เมนู Reflection
   - กลางจอ: ปุ่ม "บันทึกใหม่" สีม่วงเด่น + Streak (0 ตอนนี้)
   - ขวาบน: ชื่อครู + ปุ่ม Logout — บอกครูว่า "ทุกครั้งที่ลุกจากคอม ให้กด Logout ก่อน"

> **ห้ามอธิบาย feature ที่ครูจะไม่ใช้** — ห้ามพูดถึง multi-school, ห้ามพูดถึง AI conversation ที่จะมาใน Phase 2, ห้ามอธิบายว่า scope resolver ทำงานยังไง

**Tip:** ถ้าครูถาม "นี่อะไร?" ตอบ **สั้น** + เลื่อนต่อ. ทุกอย่างจะเข้าใจตอนใช้

## 8-23 นาที: ทำ Reflection แรก (ของจริง)

**สำคัญที่สุดของเซสชัน — อย่ารีบ**

ขอครู:
> "วันนี้คุณครูสอนคาบไหนเป็นคาบล่าสุดคะ? เล่าให้ฟังคร่าว ๆ — ไม่ต้องตอบยาว 1-2 ประโยคก็พอ"

ฟัง → จดประเด็นย่อ ๆ → ขอครู **เริ่มกดปุ่ม "บันทึกใหม่"** ด้วยตัวเอง

ผู้นำ**ห้าม**กด/พิมพ์แทน. หน้าที่ผู้นำ = "ชี้" และ "ตอบคำถาม"

ระหว่างครูกรอก:
- ครูสับสนเรื่อง "ช่องไหนกรอกอะไร" → ชี้ตามฟอร์ม
- ครูถาม "ใส่อะไรในช่องนี้ดี?" → ตอบ **"อะไรที่คุณครูจำได้ตอนนี้ก็ใส่"** ไม่ใส่ก็ได้
- ครูพิมพ์ช้า/พิมพ์ไม่คล่อง → **ไม่เร่ง**. ให้เวลาครู
- ครูเขียนยาว 1 ย่อหน้า → ดีมาก
- ครูเขียน 1 ประโยค → ก็ดี — อย่าบังคับให้เขียนเยอะ

**สังเกตและจด** (ในกระดาษส่วนตัว, ไม่ให้ครูเห็น):
- ครูใช้เวลานานสุดที่ช่องไหน?
- ครูสับสนตรงคำว่าอะไร?
- ครูดูเครียด/รำคาญตอนไหน?

ครูกด **"บันทึก Reflection"** สำเร็จ → ฉลองเล็กน้อย

## 23-30 นาที: AI สรุป + Tag + ยืนยัน

ครูจะถึงหน้ารายละเอียดของ Reflection → ชี้ให้ดูกล่องม่วง "AI ช่วยสรุป"

ขอครูกด **"สรุปอัตโนมัติ"** เอง

ระหว่าง AI สตรีม:
- พูด **"AI กำลังอ่านที่ครูเขียน แล้วลองสรุปร่างให้"** — **ไม่** ใช้ศัพท์ "LLM" "Claude" "Anthropic"
- รอเงียบ ๆ จนสตรีมจบ (5-10 วินาที)

**ขอครูอ่านสรุปเอง — ห้ามอ่านให้ครูฟัง**

หลังครูอ่านจบ:
> "คุณครูคิดว่าตรงกับที่คุณครูเขียนไหมคะ?"

3 กรณี:

**กรณี A: ครูบอก "ตรง"**
- ขอครูดู Tag ที่ AI เสนอด้านล่าง → ครูคิดว่าใช้ได้ไหม?
- กด "ยืนยันบันทึก" → จบสวย

**กรณี B: ครูบอก "ไม่ค่อยตรง"**
- ดีมาก — นี่คือสิ่งที่ระบบต้องการให้เกิด
- ขอครูกด "สรุปใหม่" → ดู version 2
- ถ้ายังไม่ตรง → ขอครูพิมพ์แก้ในกล่องเอง → ยืนยัน
- **จด** ว่า AI ผิดประเด็นไหน (จะใช้ปรับ persona ภายหลัง)

**กรณี C: ครูบอก "งง ๆ ใช้ได้/ไม่ได้ก็ไม่รู้"**
- ครูถูก. นี่คือ "ร่าง" — ครูไม่ต้องรับผิดชอบสิ่งที่ AI พูด
- ขออนุญาตยืนยันไปก่อน → "Tag อะไรไม่ตรง ลบได้นะคะ"

**กรณี D (Fallback): AI สรุปขึ้น error / สตรีมไม่กลับมา / red toast**
- พูดสั้น ๆ ว่า **"AI ของระบบติดขัดชั่วคราว เดี๋ยวเช็คให้นะคะ"** — ไม่ลึกซึ้งกับสาเหตุ
- ขอครู **พิมพ์สรุปเอง 1-2 ประโยคในกล่อง** แล้วกด "ยืนยันบันทึก" → ระบบยังทำงานได้ครบ ครูยังจบเซสชันแบบสำเร็จ
- **จด ticket** สำหรับตัวเอง: error เกิดเมื่อไร, message ขึ้นว่าอะไร — เช็คหลังเซสชันด้วย `docker compose logs app | tail -100` หรือ Sentry
- สาเหตุที่พบบ่อย: budget AI หมด (เช็ค `agents.monthly_token_budget`), Anthropic API outage, key หมดอายุ

**สำคัญ:** ห้ามชวนครู debate ว่า "AI พูดถูก/ผิด". เซสชันนี้ไม่ใช่ workshop เรื่อง AI — เป็น session ใช้งานจริง

## 30-35 นาที: ตกลง "4 สัปดาห์" + ช่องทางแจ้งปัญหา

ทบทวนกับครู:
1. **"ครูจะลองใช้ 4 สัปดาห์ — บันทึกหลังสอนเสร็จในวันเดียวกัน"**
   - ไม่ต้องบันทึกทุกคาบ — บันทึก 1 คาบที่อยากบันทึก/ที่น่าสนใจของวัน
   - บันทึกในวันเดียวกัน — ถ้าข้ามวันก็ยังบันทึกได้แต่จะหายความสด
2. **เวลาแจ้งเตือน:** ระบบจะส่งเตือน 15:30 ทุกวันทำการ ถ้าครูยังไม่บันทึก
   - **ถ้าผู้ดูแลตั้ง email reminder** → ได้รับเป็น email
   - **ถ้ายังไม่ตั้ง** → เห็นแบนเนอร์ในหน้า `/teacher` เท่านั้น (ไม่มี email)
   - บอกครูตรง ๆ ว่าจะเจอแบบไหน (อย่าให้ครูรอ email ที่ไม่มา)
3. **ครูไม่อยากบันทึกวันไหน?** บอกได้ — ไม่ผิด ไม่บังคับ
4. **เจอปัญหา/บัค → แจ้งทาง [LINE/อีเมล/มือถือ ของผู้พัฒนา]** ตอบใน 24 ชั่วโมง

ขอครู **เปิด [`teacher-cheatsheet.md`](./teacher-cheatsheet.md) ใน phone** หรือ bookmark ไว้

ถาม: **"คุณครูเห็นอุปสรรคอะไรที่จะทำให้ใช้ไม่ครบ 4 สัปดาห์ได้บ้างคะ?"**
- ฟัง → จด → ถ้าแก้ได้ตอนนี้ก็แก้ (เช่น ปรับ default คาบ, ปรับ subject), ถ้าแก้ไม่ได้ → ใส่ใน backlog

## 35-40 นาที: ปิด + นัด Check-in

1. ขอบคุณครู
2. **นัด Check-in ครั้งแรก: 3 วันหลังเซสชันนี้** (15-20 นาที, Zoom หรือเดิน 1 ทาง)
   - คำถามใน check-in:
     - บันทึกได้กี่ครั้งใน 3 วัน?
     - AI สรุปมาตรง/ไม่ตรงกี่ครั้ง?
     - มีจุดไหนกดผิด/หาไม่เจอ?
     - อยากให้เพิ่ม/เอาออกอะไรไหม?
3. **นัด Check-in ใหญ่ 4 สัปดาห์:** ระหว่างนั้นถ้าครู "หลุด" 2 วันติดต่อกัน → ผู้พัฒนาทักก่อน
4. กล่าวจบ: **"คุณครูคือผู้ใช้คนแรก — ทุกข้อที่ครูบอก จะถูกแก้/ปรับ ใน 1 อาทิตย์แรก"**

## หลังเซสชัน (ภายใน 24 ชั่วโมง)

ผู้นำต้องทำ:

1. **เปิด database** เช็คว่า Reflection แรกของครูถูกบันทึก. คำสั่งจริง:

   ```bash
   docker compose exec mysql mysql -uroot -p$MYSQL_ROOT_PASSWORD school_agent_db -e \
     "SELECT u.email, u.last_login_at,
             (SELECT COUNT(*) FROM teacher_daily_reflections r
                WHERE r.teacher_user_id = u.id) AS reflections,
             (SELECT COUNT(*) FROM reflection_ai_summaries s
                JOIN teacher_daily_reflections r ON r.id = s.reflection_id
                WHERE r.teacher_user_id = u.id) AS summaries
      FROM users u WHERE u.email = 'อีเมลครูที่เพิ่งสมัคร';"
   ```

   ควรเห็น: `last_login_at` ≠ NULL, `reflections` ≥ 1, `summaries` ≥ 1 (ถ้ากด AI สรุป)

2. **ดู token usage จริงของ Reflection แรก** — จะเป็น baseline สำหรับประเมินค่าใช้จ่ายรายเดือน:

   ```bash
   docker compose exec mysql mysql -uroot -p$MYSQL_ROOT_PASSWORD school_agent_db -e \
     "SELECT id, model_name, input_tokens, output_tokens, cache_read_tokens, total_cost_usd, created_at
        FROM ai_run_logs
        ORDER BY created_at DESC LIMIT 5;"
   ```

3. **อ่านสรุปที่ AI ทำให้ครู** → ประเมินคุณภาพเอง (ตรง/ไม่ตรง):

   ```bash
   docker compose exec mysql mysql -uroot -p$MYSQL_ROOT_PASSWORD school_agent_db -e \
     "SELECT id, summary_text, ai_tags FROM reflection_ai_summaries ORDER BY created_at DESC LIMIT 5;"
   ```

4. **เปิดสมุดจด** — เขียน:
   - 3 จุดที่ครู**ทำได้คล่อง**
   - 3 จุดที่ครู**สะดุด/งง**
   - 1-2 จุดที่ต้องแก้ใน 48 ชั่วโมง
5. **ส่งอีเมลขอบคุณครู** สั้น ๆ — ไม่เป็นทางการ. แนบลิงก์ teacher-cheatsheet ซ้ำ

## สัญญาณเตือน (Watch For)

ถ้าเห็นใน 1 อาทิตย์แรก → ทักครูทันที:

| สัญญาณ | ความหมาย | ทำอะไร |
|---|---|---|
| ครูไม่ login เลย 2 วันติด (`users.last_login_at`) | อาจมีอุปสรรคที่ไม่กล้าบอก | โทรถามตรง ๆ "ติดอะไรไหมครับ/คะ?" |
| ครู login แต่ไม่ได้บันทึก | UI งง / หาช่องไหนไม่เจอ | นัด screen-share ดูพร้อมกัน |
| ครูบันทึกแต่ไม่ขอ AI สรุป | AI สรุปครั้งแรกอาจไม่ตรงใจ | ถามว่าสรุปครั้งแรกตรงไหม |
| ครูบันทึกแล้วลบทิ้ง 2 ครั้ง | เนื้อหาที่เขียน sensitive / สับสน | คุยเรื่อง privacy + soft-delete |
| ครูพูด "ไม่มีเวลา" | จริงหรือเป็นข้ออ้าง? | **ถามครูตรง ๆ** ว่ารู้สึกใช้ฟอร์มกี่นาที — เพราะระบบยังไม่ track "time-in-form" จริง (มีแค่ createdAt). อย่าทึกทักจาก timestamp |

## สิ่งที่ "ห้าม" ทำในเซสชัน

- ห้ามแสดง dashboard ของรอง วช./ผอ. — ครูยังไม่จำเป็นต้องรู้
- ห้ามอธิบาย token budget / cost / AI model — ครูไม่ต้องรู้
- ห้ามพูดถึง Phase 2 features ที่ยังไม่มี — สร้างความคาดหวังเกินจริง
- ห้ามขอครูเขียน Reflection "ตัวอย่าง" ที่ไม่ใช่งานจริง — ทำให้รู้สึก artificial
- ห้ามนัด session ในช่วงเวลาที่ครูเหนื่อย (หลังเลิกสอน 3 คาบสด ๆ)
- **ห้ามใช้บัญชี `teacher@demo.local` กับครูจริง** — ครูต้องมีบัญชีของตัวเอง (สร้างตาม admin-quickstart §6)
